## 測試案例

### 第 7 項：每週指定星期幾

| # | 測試類型 | 輸入／操作步驟 | 預期結果 | 實際結果 | 通過？ |
|---|---|---|---|---|---|
| 1 | 黑箱 | 新增任務 → 重複 → 選「每週」 | 下方出現一～日七個 chip | | ☐ 是 ☐ 否 |
| 2 | 黑箱 | 複選「一、三、五」→ 確定 | 表單顯示「每週 一 三 五」 | | ☐ 是 ☐ 否 |
| 3 | 系統 | 承上送出，切到「每日」檢視，逐日檢查一整週 | 只在週一、三、五出現 | | ☐ 是 ☐ 否 |
| 4 | 白箱／迴歸 | 選「每週」但**一天都不選**就送出 | 沿用舊行為：只在與建立日同星期幾出現 | | ☐ 是 ☐ 否 |
| 5 | 白箱／迴歸 | 找一筆**改版前建立**的每週循環任務，不編輯它 | 行為完全不變（`recurrence_weekdays` 為 null） | | ☐ 是 ☐ 否 |
| 6 | 系統 | 編輯既有每週任務，加選星期後儲存，重開 App | 星期選擇有持久化 | | ☐ 是 ☐ 否 |
| 7 | 黑箱 | 重複規則改選「每天」或「每月」 | 星期 chip 消失，且不會誤存 weekdays | | ☐ 是 ☐ 否 |

### 第 6 項：任務拖曳排序

| # | 測試類型 | 輸入／操作步驟 | 預期結果 | 實際結果 | 通過？ |
|---|---|---|---|---|---|
| 8 | 白箱／迴歸 | **還沒拖曳過任何任務時**，觀察任務順序 | 與改版前完全一致（既有資料 `sort_order` 皆為 0，退回自動排序） | | ☐ 是 ☐ 否 |
| 9 | 平台（桌面） | 直接拖曳一列到另一列**上緣** | 插入到該列之前 | | ☐ 是 ☐ 否 |
| 10 | 平台（手機） | **長按**一列再拖曳 | 同上；短按仍是開啟編輯表單 | | ☐ 是 ☐ 否 |
| 11 | 系統 | 拖曳後重開 App | 新順序有持久化 | | ☐ 是 ☐ 否 |
| 12 | 極限值 | 把最後一列拖到**第一列之前** | 正確排到最前面（`sortOrder = 第一筆 - 1000`） | | ☐ 是 ☐ 否 |
| 13 | 極限值 | 清單只有一筆任務時嘗試拖曳 | 不崩潰，無異常 | | ☐ 是 ☐ 否 |
| 14 | 系統 | 拖曳後新增一筆任務 | 新任務排在最後 | | ☐ 是 ☐ 否 |

### 第 9 項：一層子任務

| # | 測試類型 | 輸入／操作步驟 | 預期結果 | 實際結果 | 通過？ |
|---|---|---|---|---|---|
| 15 | 黑箱 | 編輯某頂層任務 → 點「新增子任務」 | 關閉編輯表單、開啟新增表單；送出後該任務縮排顯示在父任務下方 | | ☐ 是 ☐ 否 |
| 16 | 黑箱 | 把一個頂層任務拖到另一個頂層任務的**列身**（非上緣） | 變成其子任務並縮排 | | ☐ 是 ☐ 否 |
| 17 | 白箱／限制 | 嘗試把任務拖到**子任務**的列身上 | **不允許**變成子任務的子任務（只會被判定為「插入之前」） | | ☐ 是 ☐ 否 |
| 18 | 白箱／限制 | 把一個**已經有子任務**的任務拖到別的任務列身上 | **不允許**（同上，最多插入之前） | | ☐ 是 ☐ 否 |
| 19 | 黑箱 | 編輯一個**子任務** | 表單**不顯示**「新增子任務」按鈕 | | ☐ 是 ☐ 否 |
| 20 | 系統 | 拖曳中觀察列表尾端 | 出現放置區；把子任務拖進去會移回頂層 | | ☐ 是 ☐ 否 |
| 21 | 系統／破壞性 | 刪除一個**有子任務**的父任務 | 子任務一併刪除，不留孤兒 | | ☐ 是 ☐ 否 |
| 22 | 白箱／迴歸 | 編輯一個子任務（改標題）後儲存 | 仍是子任務、順序不變（`parentTaskId`/`sortOrder` 沒被重設） | | ☐ 是 ☐ 否 |
| 23 | 白箱／迴歸 | 編輯一個**循環**任務（改標題）後儲存 | 先前的完成紀錄仍在（`completedDates` 沒被清掉） | | ☐ 是 ☐ 否 |
